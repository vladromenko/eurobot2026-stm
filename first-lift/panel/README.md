# test_low — терминальный пульт Eurobot 2026

Полноэкранный пульт запускается прямо внутри SSH-сеанса. Браузер, веб-сервер,
логины и дополнительные пароли не нужны. Слева показаны состояние робота и все
клавиши, справа — живой журнал: действие, команда прошивки, отправленный пакет
`TX`, ответ контроллера `RX`, результат и время ответа.

## Структура программы

Пульт теперь разбит по назначению. Запуск для пользователя не изменился:
`bash start.sh` по-прежнему открывает тот же интерфейс и те же клавиши.

```text
test_low/
├── start.sh                    запуск и освобождение Serial-порта
├── robot_console_2026.py       короткая точка входа
└── robot_panel/
    ├── ui.py                   экран и привязка клавиш
    ├── chassis.py              пакеты движения и Maxon
    ├── gripper.py              подъём, оси, створки и блоки
    ├── lift2.py                Stepper Output 2 и сервы S1/PWM5, S3/PWM6
    ├── vacuum.py               насосы и клапаны
    ├── diagnostics.py          датчики, BMS и энкодеры
    ├── controller.py           единая отправка пакета и ожидание ответа
    ├── protocol.py             FF FF, длина, данные и CRC
    ├── command_codes.py        номера команд прошивки
    ├── dispatcher.py           неблокирующая очередь команд
    ├── guided_tests.py         описания пошаговых аппаратных тестов
    ├── logs.py                 журналы JSONL
    ├── demo.py                 симулятор контроллера
    └── selftest.py             автономная проверка протокола
```

Например, клавиша `D` обрабатывается в `ui.py`, вызывает `set_speed()` из
`chassis.py`, после чего `controller.py` передаёт данные в `protocol.py` и
пишет готовый бинарный пакет в Serial. Подъём и остальные команды руки можно
смотреть отдельно в `gripper.py`, а присоски — в `vacuum.py`.

## Запуск на роботе

Скопируйте папку с Mac:

```bash
scp -r "/Users/vladromenko/Desktop/Eurobot/test_low" <user>@<robot_ip>:~/
```

Подключитесь к роботу и запустите пульт:

```bash
ssh -t <user>@<robot_ip>
cd ~/test_low
bash start.sh
```

Перед открытием интерфейса программа сама делает безопасную проверку связи:

1. до трёх раз отправляет реализованный в этой прошивке `PING`;
2. запрашивает текущую скорость командой `GET_SPEED`;
3. допускает к управлению только после корректного ответа длиной 12 байт.

Проверить только UART, не отправляя команды исполнительным механизмам:

```bash
cd ~/test_low
bash start.sh --check-only
```

Ожидаемый результат:

```text
Связь подтверждена: STM32 отвечает по протоколу прошивки 2026.
CHECK OK: управляющие команды не отправлялись.
```

Используйте английскую раскладку клавиатуры. Для одновременного отображения
управления и журнала желательно развернуть окно терминала хотя бы до `104x34`.

`start.sh` сам:

- остановит Docker-контейнер `communication`, если тот занимает STM32;
- найдёт последовательный порт контроллера;
- при необходимости создаст `.venv` и установит только `pyserial`;
- запустит терминальный пульт;
- после выхода вернёт контейнер `communication`, если он работал до теста.

Окружение активировать вручную не нужно. Скрипт всегда запускает
`.venv/bin/python` напрямую и проверяет наличие PySerial именно внутри `.venv`.

## Клавиши

### Движение

| Клавиша | Действие |
|---|---|
| `M` | включить или выключить двигатели Maxon |
| `V` | остановить базу, отключить Maxon и освободить удержание колёс |
| `W` / `S` | вперёд / назад по оси X |
| `A` / `D` | влево / вправо по оси Y |
| `Q` / `E` | поворот в две стороны |
| `Space` | немедленно остановить базу |
| `-` / `=` | уменьшить / увеличить линейную скорость |
| `,` / `.` | уменьшить / увеличить скорость поворота |

Клавишу движения нужно удерживать. SSH не сообщает программе отдельное событие
«клавиша отпущена», поэтому используется watchdog: если повтор клавиши не пришёл
за 0,30 секунды, пульт отправляет нулевую скорость.

### Захваты и присоски

| Клавиша | Действие |
|---|---|
| `1` / `2` | выбрать захват |
| `P` / `O` | включить / выключить присоски выбранного захвата |
| `3` / `4` | отдельно включить / выключить насосы по текущей маске |
| `5` / `6` | отдельно открыть / закрыть клапаны по текущей маске |
| `[` / `]` | уменьшить / увеличить 4-битную маску присосок |
| `Z` / `X` / `C` | подъём захвата: вверх / середина / вниз |
| `Y` / `H` | закрыть / открыть боковые захваты |
| `R` / `F` | удерживать: вертикальная ось шагами +5 / −5 мм, диапазон 0…255 мм |
| `T` / `G` | удерживать: слайдер шагами +5 / −5 мм, диапазон −37…37 мм |
| `7` / `8` | мягко повернуть тот же мотор узла насосов, что управляется `U/J`: −5° / +5°; текущее положение считывается автоматически |
| `U` / `J` | мягко доворачивать мотор `CURSOR` на +5° / −5° при каждом нажатии |
| `Shift+U` / `Shift+J` | полное горизонтальное / вертикальное положение `CURSOR` |
| `B` / `N` | развести / свести блоки |
| `I` | повернуть выбранные текущей маской блоки |
| `K` | вернуть повёрнутые блоки обратно |
| `Shift+K` | старый полный цикл: развести → повернуть по маске → свести |
| `L` | полная диагностика: координаты, скорость, BMS, колёса, стартовый шнур и 9 концевиков |

### Новый пошаговый подъём — Stepper Output 2

| Клавиша | Действие |
|---|---|
| `9` | открыть отдельный экран безопасного пошагового управления Lift2 |
| `A` | разрешить Stepper 2 и сервы; само движение не начинается |
| `S` | остановить Stepper 2 в текущей точке |
| `O` | полностью отключить Stepper 2, S1/PWM5 и S3/PWM6 |
| `Z` | принять текущую точку Stepper 2 за ноль |
| `R` / `F` | Stepper 2: один малый шаг +25 / −25 микрошагов |
| `Y` / `H` | S1 на PWM5: плавно +20 / −20 мкс |
| `T` / `G` | S3 на PWM6: плавно +20 / −20 мкс |
| `Backspace` | вернуться в обычное ручное управление |

Каждое нажатие дожидается завершения предыдущего малого
шага. Поэтому команды не накапливаются и механизм не срывается в
длинное резкое движение. Эти клавиши управляют новым узлом только после входа
в отдельный режим клавишей `9`; в обычном экране их штатные функции сохранены.

При старте и при выходе новый узел переводится в `OFF`. Клавиша `0` тоже
отключает все три новых выхода. Первую проверку сервы делайте без нагрузки:
первая команда выставит нейтраль 1500 мкс, а затем будут малые шаги.

## Порядок первого запуска нового узла

1. Полностью обесточите робота.
2. Подключите шаговый мотор к `Stepper Output 2` — второму снизу
   из четырёх шаговых разъёмов.
3. Сервы: коричневый — `GND`, красный — `+6V`, оранжевый — сигнал.
   Серву `S1` подключите к `PWM5`, серву `S3` — к `PWM6`.
4. Прошейте собранный `firmware.hex` по командам из итоговой
   инструкции.
5. Выполните `./start.sh --check-only`. Это только проверка связи.
6. Запустите `./start.sh`, нажмите `9`, затем `A` и проверьте по одному
   `R` / `F`. Если направление неверное, остановите `S` и
   поменяйте местами одну пару обмотки только на обесточенном роботе.
7. Проверьте по одному малому шагу S1/PWM5 и S3/PWM6. Закончите `O`.

### Экран и безопасность

| Клавиша | Действие |
|---|---|
| `Tab` | переключить журнал в полноэкранный режим и обратно |
| `Backspace` | вернуться из Lift2 или аппаратных тестов в ручное управление |
| `?` | открыть режим пошаговых аппаратных тестов |
| `0` | аварийно остановить базу, отключить Maxon, насосы и клапаны |
| `Esc` | безопасно завершить: остановить базу и отключить Maxon |

Любая команда механизма сначала останавливает базу. При обычном выходе присоски
автоматически не отключаются, чтобы не уронить удерживаемый объект. Для полного
отключения используйте `0`.

Размер мягкого шага мотора на клавишах `7` / `8` задаётся отдельно параметром
`--cursor-jog-step` (целое число 1…20°, по умолчанию 5°). Обычный запуск через
`./start.sh` уже использует шаг 5°. Клавиши `U` / `J` используют тот же мягкий
шаг и поэтому срабатывают повторно; полные положения сохранены на
`Shift+U` / `Shift+J`. `T` / `G` управляют только рейкой и не изменены. Перед
каждым мягким шагом панель считывает реальный угол Dynamixel 106 и ограничивает
доводку рабочим диапазоном 80…198°.
В установленном файле прошивки для штатной команды `CURSOR` остался старый ID 98,
поэтому панель отправляет и мягкие шаги, и полные положения напрямую на
найденный привод 106 и не ждёт ошибочный полуторасекундный тайм-аут прошивки.

Интерфейс не зависает во время работы механизма: остальные нажатия принимаются,
показываются в строке `queued` и выполняются последовательно. Повторяющиеся
команды одной оси объединяются — например, при удержании `R` очередь не
заполняется устаревшими промежуточными позициями.

Прошивка 2026 использует один общий исполнительный канал `gripper_cmd` для
подъёмов, присосок, створок, курсора, слайдера и механизмов блоков. Поэтому эти
команды физически выполняются по очереди. Движение базы во время долгой команды
механизма запрещено: иначе прошивка могла бы задержать команду остановки.

## Пошаговое тестирование

Нажмите `?`, выберите узел стрелками или `J/K` и нажмите `Enter`. Пульт:

1. покажет назначение узла и допустимые крайние значения;
2. попросит ввести выбранные значения;
3. потребует написать `RUN` перед отправкой команды;
4. попросит поставить `PASS`, `FAIL` или `SKIP`;
5. позволит записать наблюдение обычным текстом.

Результаты сохраняются отдельно в файле вида:

```text
robot_2026_test_results_20261012_153000.jsonl
```

В меню находятся тесты базы, присосок, подъёма захвата, вертикальной оси,
слайдера, боковых створок, курсора, разведения и поворота блоков, а также
полной диагностики датчиков, BMS и колёс.

## Нужен ли ROS и несколько терминалов

Нет. Этот пульт напрямую работает с HL-RTU интерфейсом STM32. Достаточно одного
SSH-сеанса и команды `bash start.sh`. В отдельном терминале запускать ROS-ноды,
входить в Docker-контейнер или вручную публиковать ROS-команды не нужно.

## Журнал

Все обмены с STM32 одновременно видны справа и сохраняются рядом со скриптом:

```text
robot_2026_console_log_20261012_153000.jsonl
```

Каждая строка — отдельная JSON-запись с действием, кодом команды, байтами `TX`,
байтами `RX`, результатом и задержкой. Файл остаётся после выхода и пригоден для
разбора теста.

## Важные ограничения

- Пульт рассчитан только на прошивку 2026 года и специально требует флаг
  `--confirm-2026`, который добавляет `start.sh`.
- Первый тест движения выполняйте с вывешенными колёсами и небольшой скоростью.
- В изученной прошивке команды насосов и клапанов для захватов 1 и 2 используют
  одни и те же SPI-выходы. Поэтому сначала проверьте присоски без груза и
  убедитесь, какой физический контур срабатывает.
- Команды сброса платы, отключения связи, калибровки колёс и прямого управления
  AX-сервоприводами намеренно не добавлены: это не обычные функции эксплуатации.

## Если проверка связи не проходит

Скорость менять не нужно: в приложенной прошивке `USART1` настроен на
`921600 baud, 8N1`, а пакет PING равен `ff ff 02 00 fd`. CP2102 в списке Linux
подтверждает только наличие USB–UART адаптера, но не связь адаптера со STM32.

Без перепрошивки проверьте:

- общий `GND` между CP2102 и платой;
- `TX` адаптера идёт на `PA10` (`USART1_RX`) STM32;
- `RX` адаптера идёт на `PA9` (`USART1_TX`) STM32;
- на линиях уровень 3,3 В, нет обрыва и TX/RX не соединены одноимённо;
- STM32 не удерживается в RESET и выполняет основную программу.

Обнаружение микроконтроллера командой `st-info --probe` подтверждает SWD-связь,
но само по себе не подтверждает выполнение FreeRTOS и задачи `TerminalTask`.
