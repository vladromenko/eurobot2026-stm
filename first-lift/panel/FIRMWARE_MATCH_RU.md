# Сверка с eurobot2026-stm-zagorodnyuk

Пульт сверен с исходниками прошивки из переданного архива. Для управления
не требуется менять скорость или формат пакета.

## UART и протокол

- `Core/BSP/board_hw_config.c`: USART1, 921600 бод, 8 бит, без чётности,
  один стоп-бит, приём и передача.
- `Core/BSP/board_gpio_config.c`: PA9 = USART1_TX, PA10 = USART1_RX, AF7.
- `Core/Lib/hl_rtu.c`: пакет `FF FF | length | command | data | checksum`;
  checksum — инверсия младшего байта суммы `length + command + data`.
- `Core/App/terminal_cmd_handlers.c`: PING имеет код `0x00` и отвечает пустым
  пакетом. Запрос скорости `0x05` отвечает 12 байтами (три `float32`).

Поэтому запрос PING без данных должен выглядеть так:

```text
ff ff 02 00 fd
```

## Команды клавиатуры

Сверены номера команд и данные для скорости базы, Maxon, захватов 1/2,
подъёма, боковых створок, курсора, вертикальной оси, слайдера, насосов,
клапанов и механизмов блоков. Существенные значения:

- захваты: ID `1` и `2`;
- подъём: `0` вверх, `2` середина, `1` вниз;
- боковые створки: `1` закрыть, `0` открыть;
- насосы и клапаны: 4-битная маска, бит `1` оставляет соответствующий выход
  включённым;
- вертикальная ось: один байт абсолютной высоты в миллиметрах;
- слайдер: знаковое `int32` little-endian; безопасный программный диапазон
  пульта `−37…37 мм` соответствует вычислению и ограничению угла в прошивке.

## Что исправлено в пульте

- `start.sh` теперь всегда использует локальный `.venv` и не переустанавливает
  PySerial при каждом запуске из-за проверки не того Python.
- Перед управлением выполняются три попытки PING и read-only `GET_SPEED`.
- Порт открывается как эксклюзивный, с явно выключенным программным и
  аппаратным flow control.
- Таймаут относится ко всему ответу; в журнал попадают частично полученные
  байты, если они были.
- Если прошивка не отвечает, исполнительные команды и очистка по UART не
  отправляются. Сообщение указывает точные выводы PA9/PA10 для проверки.

## Вывод по исходному таймауту

Исходный пульт уже отправлял правильный PING на правильной скорости. Пустой RX
на 115200 и 921600 вместе с рабочим CP2102 и видимым по SWD STM32 не доказывает
исправность UART-соединения. Наиболее вероятны обрыв/перепутанные TX-RX/нет
общей земли либо STM32 не дошёл до работающей `TerminalTask`. Эти причины нельзя
устранить изменением Python-пакета и для их проверки перепрошивка не нужна.
