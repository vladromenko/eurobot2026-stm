# Прошивка Eurobot 2026: инструкция и история изменений

## Путь сборки

```text
cmake/sources.cmake + CMakeLists.txt
        ▼
CMake preset debug/release → Ninja → arm-none-eabi-gcc
        │ Cortex-M4F, fpv4-sp-d16, hard float
        ▼
GNU startup + GCC-порт FreeRTOS + STM32F407VG_FLASH.ld
        ▼
firmware.elf → firmware.bin / firmware.hex / firmware.map
        ▼
cmake/check_firmware.py — векторы, ISR, память, CPU-флаги, образы
        ▼
OpenOCD → ST-LINK → SWD → STM32F407VGTx
        ▼
tools/monitor_stm32.py — Flash, FreeRTOS, tick, PCA9685
        ▼
стендовые проверки робота
```

## Что изменено

### Переход с Keil на CMake/GCC

Изначально проект собирался ARMCC 5 в Keil MDK-ARM. Список исходников, defines, include-пути, CPU/ABI-флаги и раскладка памяти перенесены в CMake; ARMASM startup заменён GNU startup из CMSIS, RVDS-порт FreeRTOS — портом `GCC/ARM_CM4F`, добавлены linker script и `cmake/gcc_runtime.c` (`_init`/`_fini`). Файлы Keil и неиспользуемые части вендорских библиотек удалены; итоговый образ при этом побайтово не изменился.

Сохранены `cortex-m4`, Thumb, `fpv4-sp-d16`, hard float, short enums/wchar, unsigned char и `-O0` в Debug. Release использует `-Os`, кроме `l6474_drvr.c`, которому оставлен `-O0` (bit-bang тайминги).

### Запуск DemoTask

`DemoTask` по умолчанию не создаётся, как в исходной прошивке. Для проверки выходов SPI GPO раскомментируйте `DemoTask.CreateTask(4)` в `Core/App/main.c` **и** нужный демо-режим (например, `SPI_GPO_DEMO`) в `Core/OS_Tasks/demo_task.c`.

Внимание: без включённого демо-режима цикл задачи пустой и не содержит `vTaskDelay`. С приоритетом 4 такая задача забирает весь процессор, и все задачи с меньшим приоритетом, включая терминал UART1, перестают выполняться: плата не отвечает даже на PING.

### Исправление PCA9685/I2C2

В `Core/BSP/i2c2.c`:

- бесконечные циклы ожидания заменены ожиданиями с тайм-аутом 20 мс;
- обрабатываются NACK (`AF`), bus error, arbitration lost и overrun;
- при ошибке формируется STOP и восстанавливаются ACK/POS;
- исправлена последовательность чтения 1, 2 и нескольких байт;
- возвращаются диагностические коды вместо вечного зависания.

В `Core/BSP/board_hw_config.c` частота, передаваемая в `LL_I2C_ConfigSpeed`, исправлена с 84 МГц на 42 МГц. При APB1 divider 4 это реальная частота PCLK1; заданная скорость I2C остаётся 100 кГц.

В `Core/App/main.c` результат сохраняется в `PCA9685_InitStatus`. Ошибка PCA9685 не останавливает создание задач и запуск FreeRTOS:

| Статус | Значение |
|---|---|
| `0` | PCA9685 инициализирован |
| `-2` | тайм-аут I2C |
| `-3` | устройство не подтвердило адрес |
| `-4` | ошибка шины |
| `-5` | потеря арбитража |
| `-6` | переполнение |

Адрес `0x40`, PB10/PB11, 100 кГц и команды PCA9685 не менялись.

### Программирование платы

Вывод NRST к ST-LINK не подключён, поэтому reset выполняется программно (SYSRESETREQ через AIRCR). STM32CubeProgrammer на этой плате завершался `DEV_TARGET_RESET_ERR`; проверенная запись выполнялась `st-flash --hot-plug --reset`. OpenOCD по умолчанию тоже использует software reset (ST-LINK без `srst`); на самой плате прошивка через OpenOCD ещё не проверялась.

Перед первой записью был сохранён полный дамп Flash 1 МБ. Отдельного пользовательского bootloader нет: единственная таблица векторов начинается с `0x08000000`. Заводской ROM bootloader STM32 находится в system memory и записью не стирается.

## Ошибки исходной и первой собранной прошивки

| Ошибка | Проявление | Исправление |
|---|---|---|
| Проект зависел от ARMCC/Keil | CMake/GCC не могли воспроизвести сборку | Перенесены sources, defines, includes, CPU/ABI-флаги, startup, FreeRTOS port и linker layout |
| Не было GNU linker/runtime-конфигурации | Нельзя было корректно получить запускаемый ELF/BIN/HEX | Добавлены linker script, `_init`/`_fini`, objcopy и аудит секций/векторов |
| `DemoTask` с пустым циклом и приоритетом 4 | Терминал UART1 не отвечал: задача с приоритетом 1 ни разу не получала процессор | `DemoTask` снова не создаётся по умолчанию |
| Бесконечное ожидание I2C `ADDR` | CPU работал, но tick/tasks оставались нулевыми; FreeRTOS не запускался | Добавлены тайм-ауты, обработка NACK/ошибок и освобождение транзакции |
| В `LL_I2C_ConfigSpeed` передавалось 84 МГц вместо PCLK1=42 МГц | I2C работал примерно на 50 кГц вместо заданных 100 кГц | Передаётся правильная частота 42 МГц |
| Результат `PCA9685.Init()` игнорировался | Причину отказа нельзя было увидеть, а зависание происходило до задач | Результат хранится в `PCA9685_InitStatus`; запуск продолжается |
| CubeProgrammer требовал reset, которого не было на ST-LINK | `DEV_TARGET_RESET_ERR` до записи | Прошивка через OpenOCD с software reset |

## Сборка

```bash
cmake --preset debug
cmake --build --preset debug
cmake --build --preset debug --target check
```

Release — то же самое с `release`. Debug следует проверять первым. Успешный `check` подтверждает структуру образа, но не работу механизмов.

## Загрузка

```bash
cmake --build --preset debug --target flash
```

Цель пересобирает прошивку, записывает `firmware.elf` через OpenOCD, сверяет записанное и делает reset. Ожидаемые строки: `** Verified OK **` и `** Resetting Target **`. В VS Code то же делает кнопка Flash.

Перед записью другой платы сначала сохраните её Flash:

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c "init; dump_image backup-flash.bin 0x08000000 0x100000; exit"
```

## Отладка

В VS Code: F5 → «Debug (OpenOCD)» (сборка, прошивка, остановка на `main`, список задач FreeRTOS) или «Attach (OpenOCD)» без перепрошивки. Нужно расширение Cortex-Debug и `arm-none-eabi-gdb` в `PATH`.

## Проверка после загрузки

```bash
python3 tools/monitor_stm32.py
```

Ожидается:

- Flash совпадает с локальным `firmware.bin`;
- `SystemCoreClock = 168000000`;
- `PCA9685_InitStatus = 0` при подключённом исправном модуле;
- `xSchedulerRunning = 1`;
- не менее 8 задач;
- tick растёт примерно на 1000 в секунду;

Если `PCA9685_InitStatus = -3`, проверить общий GND, логическое питание VCC 3.3 В, PB10→SCL, PB11→SDA, подтяжки SDA/SCL и перемычки A0…A5. Питание сервоприводов `V+` не заменяет логическое VCC микросхемы.

UART1 можно проверить read-only запросами:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install pyserial
python3 tools/serial_read_test.py --list
python3 tools/serial_read_test.py --port /dev/cu.НУЖНЫЙ_ПОРТ --command speed
```

## Импеллер (турбинка)

Турбинка «DC 12–12.6V 120000 RPM», вариант Mode 03 (resistance speed): встроенный контроллер, скорость задаётся постоянным напряжением на среднем выводе потенциометра, короткое нажатие кнопки переключает вкл ↔ выкл. Исходное задание и прототип на ESP32 — [IMPELLER_TASK_RU.md](IMPELLER_TASK_RU.md), [impeller_esp32_prototype.ino](impeller_esp32_prototype.ino).

### Подключение

- **Силовое питание — только напрямую от аккумулятора 3S** (провода ≥ 1,5 мм², XT30/XT60, предохранитель 15–20 А). Ток до ~13 А, на старте больше. Разъёмы платы `+12V` / Power Output не использовать.
- **Общая земля:** минус аккумулятора турбинки соединён с GND платы.
- **Скорость:** разъём PWM8 (PA3, TIM5_CH4), контакт PWM; +6V не использовать. PA3 → 10 кОм → средний провод потенциометра, от этой точки 1–10 мкФ на GND. Потенциометр отпаян, его опорный провод заизолирован, земляной — на GND. `U ≈ 3,3 В × duty`.
- **Кнопка:** 2N7000 параллельно родной кнопке. D — сигнальный провод кнопки, S — GND, G — GPIO5 (PA8, контакт 5 28-пинового разъёма) + 100 кОм с затвора на GND. HIGH = нажата.

После `Impeller.Init()` TIM5 работает на 20 кГц с предделителем 0, поэтому **PWM5–PWM8 нельзя использовать под RC-сервы**. Назначение выводов — в `robot_gpio_defines.h` (`IMPELLER_*`).

### Поведение

| Состояние | Код | Что происходит |
|---|---|---|
| `OFF` | 0 | сигнал `V_STOP`, кнопка отпущена |
| `STARTING` | 1 | нажатие `IMPELLER_PRESS_MS`, затем пауза `IMPELLER_BOOT_DELAY_MS` при 0 % |
| `ON` | 2 | скорость плавно идёт к заданной, `IMPELLER_RAMP_PCT_PER_S` |
| `STOPPING` | 3 | плавно до 0, пауза `IMPELLER_STOP_DELAY_MS`, нажатие |

- После сброса: сигнал скорости 0 В, кнопка отпущена, ничего не нажимается.
- Включение в `ON` и выключение в `OFF` игнорируются. Команда, пришедшая во время `STARTING`/`STOPPING`, выполняется после окончания текущей последовательности: выключение во время разгона — турбинка включится и сразу плавно выключится.
- **Обратной связи нет.** Кнопка — переключатель, прошивка знает только своё программное состояние. Если турбинку включили/выключили родной кнопкой или контроллер перезапустился от просадки питания, состояние разойдётся с реальным. Восстановить: в `OFF` прошивки привести турбинку в выключенное состояние (родная кнопка или снять питание турбинки). Аппаратного обесточивания нет — на стенде нужен физический выключатель питания турбинки.
- Конец матча (99 с, не в `bench`): `StopAllActuators()` выключает импеллер, после `COMM_ENABLE = 0` команды включения отклоняются. Выключение принимается всегда.
- `IMPELLER_MAX_SPEED_PCT` (сейчас 100 %, для первых тестов было 30 %) ограничивает любую команду скорости.

### Команды терминала

Ответ на команды: `data[0]` = 1 принято / 0 ошибка (длина, параметр, `COMM_ENABLE = 0`), `data[1]` = состояние (таблица выше), `data[2]` = текущая скорость после рампа, %.

| cmd | Запрос | Действие |
|---|---|---|
| `0x30` `BOARD_IMPELLER_ON` | `data[0]` = скорость 0..100 % | включить, если выключен, и задать скорость; если уже включён — только скорость |
| `0x31` `BOARD_IMPELLER_OFF` | — | плавно остановить и выключить |
| `0x33` `BOARD_IMPELLER_PRESS` | `data[0..1]` = мс (uint16), 1..2000 | нажать кнопку, состояние в прошивке не меняется (`./start.sh --impeller-press N`, клавиша P) |
| `0x34` `BOARD_IMPELLER_SYNC` | `data[0]` = 0 выкл / 1 вкл | сказать прошивке реальное состояние без нажатия, например после включения родной кнопкой (`./start.sh --impeller-sync on|off`, клавиши U / N). «Выкл» принимается и после конца матча |
| `0x32` `BOARD_IMPELLER_SET_MV` | `data[0..1]` = мВ (uint16, little-endian), 0..3300 | опорное напряжение сигнала при включении, `0` — управление скоростью. Сохраняется до сброса платы. Ответ на 2 байта длиннее: `data[3..4]` = действующее значение, мВ |

С компьютера или с робота (`reset10`) — через [start.sh](../start.sh) и [tools/teleop.py](../tools/teleop.py), порт USART1 ищется автоматически или указывается первым аргументом:

```bash
./start.sh --impeller on                       # одна команда и выход, 100 % по умолчанию
./start.sh --impeller on --impeller-speed 40   # другая скорость
./start.sh --impeller off
./start.sh                                     # клавиатура: T / Y — вкл / выкл (100 % по умолчанию), < / > — скорость ±5 %, J / K — опорное ±100 мВ, H — опорное 0
```

При выходе из клавиатурного режима (X, Esc) отправляются нулевая скорость и выключение импеллера.

Ответ приходит сразу — команда не ждёт окончания нажатия и разгона. Отдельной команды статуса нет: состояние и скорость приходят в ответе на каждую команду, повторная `0x30` во включённом состоянии только меняет скорость. Клиент верхнего уровня (`robot_console_2026.py`, код на `reset10`) в этом репозитории не хранится — команды туда нужно добавить отдельно.

### Калибровка

Константы — в начале [impeller.h](../Core/Lib/Include/impeller.h). Сейчас `V_MIN = 500 мВ`, `V_MAX = 3300 мВ`, `PRESS_MS = 200 мс` — **не проверены**, заменить значениями со стенда ESP32.

**Опорное напряжение (режим калибровки).** Значение после сброса — `IMPELLER_CALIBRATION_MV` в `impeller.h` (сейчас **3300**), во время работы меняется командой `0x32` / `./start.sh --impeller-mv N`. Если не 0:

1. при включении сначала на сигнал подаётся это напряжение, через `IMPELLER_SIGNAL_SETTLE_MS` (500 мс, 5τ RC-фильтра 10 кОм × 10 мкФ) — нажатие кнопки, потом пауза `IMPELLER_BOOT_DELAY_MS`;
2. во включённом состоянии сигнал всё время равен этому напряжению, скорость из `0x30` не используется;
3. напряжение, заданное командой `0x32` (или J / K), действует **сразу в любом состоянии**, как команда `v` на ESP32: можно включить турбинку родной кнопкой и менять напряжение. Выключение (`0x31`) и конец матча возвращают 0 В; значение сохраняется и снова подаётся при следующем включении;
4. после сброса, в `OFF` без команды `0x32` и в конце матча — 0 В.

`0` — обычное управление скоростью: нажатие при 0 В, затем плавный разгон. Напряжение выше `V(IMPELLER_MAX_SPEED_PCT)` отклоняется.

Команды калибровки в терминале нет: напряжения подбираются на стенде ESP32, затем переносятся в константы и прошивка пересобирается.

1. Турбинка закреплена; для первых проверок поставить `IMPELLER_MAX_SPEED_PCT = 30`.
2. Проверить на роботе: `0x30` с малой скоростью (1–5 %) — мотор должен уверенно крутиться, иначе поднять `IMPELLER_V_MIN_MV`.
3. `IMPELLER_V_MAX_MV` проверять, только временно подняв `IMPELLER_MAX_SPEED_PCT`.
4. Если у контроллера 0 В = максимум, поставить `IMPELLER_INVERT 1`. Внимание: тогда до `Impeller.Init()` (сразу после сброса) PA3 = 0 В, то есть «максимум».

Проверка логики без платы: `python3 tools/test_impeller.py` (нужен `cc`).

### Стендовая проверка без турбинки

- После сброса: на выходе RC-фильтра ≈ 0 В, PA8 = 0.
- `0x30` с 50 %: импульс 3,3 В на PA8 длиной 200 мс, через ~1,2 с напряжение фильтра плавно растёт до `V_MIN + (V_MAX − V_MIN) × 0,5` ≈ 1,9 В; частота на PA3 — 20 кГц.
- На стоке 2N7000 во время импульса ≈ 0 В.
- `0x31`: напряжение плавно падает до 0, через 300 мс — импульс 200 мс на PA8.
- Конец матча (не `bench`): напряжение падает до 0, затем импульс на PA8.

При питании от слабого источника мотор только дёргается и останавливается — скорее всего, причина в питании, а не в сигнале.

## Что ещё нужно проверить

Перед тестами движения зафиксировать робот, поднять колёса и обеспечить быстрое отключение силового питания.

1. Подтвердить `PCA9685_InitStatus = 0` и измерить SCL/SDA логическим анализатором: адрес `0x40`, частота около 100 кГц.
2. Осциллографом проверить реальные выходы SPI GPO 1–4: 250 мс ON, 250 мс OFF. SRAM-регистр является только программной тенью.
3. Проверить UART1 921600 8N1 и команды чтения скорости/координат/кнопок.
4. Проверить UART3 Dynamixel 1 Мбит/с, USART6 Maxon 2 Мбит/с, UART4 BMS и UART5 Serial.
5. По одному проверить концевики, энкодеры, PWM, шаговый привод, сервоприводы PCA9685, WS2812B, насосы и клапаны.
6. Проверить аварийную остановку и `StopAllActuators` до испытаний автономного поведения.
7. Измерить high-water mark стеков задач и MSP; проверить отсутствие HardFault, NaN и повреждения SRAM при длительной работе.
8. Выполнить длительный Debug-прогон, затем отдельно повторить весь стендовый тест Release-сборки.
9. Сравнить координаты, направления колёс и механику захватов с прежней Keil-прошивкой.

## Известные нерешённые проблемы

- В `robot_behavior_routine.c` выражение с `strategy++` изменяет и читает переменную без определённого порядка; компилятор предупреждает о неопределённом поведении.
- В `gripper_task.c` переменная `move_speed` может остаться неинициализированной для неожиданного значения направления.
- GCC собирает проект с `-fshort-wchar` (наследие Keil), но стандартные библиотеки GNU используют 32-битный `wchar_t`. В текущем коде wchar API не используется; это нужно помнить при будущих изменениях.
- Аппаратно подтверждён запуск Debug после исправления I2C. Полное поведение робота и Release ещё не квалифицированы.

Эти два предупреждения прикладного кода нужно исправить после согласования ожидаемого поведения, до допуска автономного движения.
