# Задача: управление импеллером (турбинкой) с платы RESET

Документ — задание для агента, который работает в этом репозитории (`eurobot2027-stm`).
Нужно добавить в прошивку STM32F407 управление высокооборотной турбинкой: включение/выключение и скорость, плюс команду терминала для верхнего уровня.

Прототип этого управления уже сделан и проверяется на ESP32: [impeller_esp32_prototype.ino](impeller_esp32_prototype.ino). Логику (рамп, «нажатие» кнопки, калибровка напряжения) нужно перенести в стиль этого проекта.

Перед правкой кода прочитай `README.md`, `CodeStyle.txt`, `docs/USAGE_RU.md` и пройди раздел «Открытые вопросы» в конце — их нужно задать пользователю, а не решать молча.

---

## 1. Что за устройство

Китайская турбинка «DC 12–12.6V 120000 RPM violent brushless fan», вариант **Mode 03 (resistance speed)** — со встроенным контроллером бесколлекторного мотора, потенциометром и кнопкой. Документации у производителя нет, всё ниже получено замерами и опытами.

| Параметр | Значение |
|---|---|
| Питание | 12–12,6 В (3S LiPo) |
| Мощность | до ~160 Вт → **ток до ~13 А**, на старте больше |
| Провода | красный (+12 В), чёрный (−), 3 провода потенциометра, 2 провода кнопки |
| Скорость | задаётся **постоянным напряжением** на среднем выводе потенциометра (контроллер его измеряет). Диапазон калибруется, см. ниже |
| Вкл/выкл | **короткое нажатие** кнопки (нажал-отпустил, ~200 мс) переключает вкл ↔ выкл. Длинное удержание не нужно |
| Кнопка | один провод — земля контроллера, второй — вход с подтяжкой (3,3–5 В), нажатие замыкает его на землю |

Калибровочные значения (заполнятся по результатам опытов на ESP32; до этого — параметры по умолчанию):

| Константа | Смысл | Значение сейчас |
|---|---|---|
| `IMPELLER_V_MIN` | напряжение сигнала, при котором мотор начинает крутиться | 0,5 В (не проверено) |
| `IMPELLER_V_MAX` | напряжение, выше которого скорость не растёт | 3,3 В (не проверено) |
| `IMPELLER_PRESS_MS` | длительность «нажатия» кнопки | 200 мс |

Известная нерешённая проблема из опытов: при питании от слабого источника мотор только дёргается и останавливается. Скорее всего, это питание, а не сигнал. На логику прошивки не влияет, но учитывай при стендовой проверке.

## 2. Подключение к плате RESET

**Силовое питание турбинки — только напрямую от аккумулятора** (провода ≥ 1,5 мм², XT30/XT60, предохранитель 15–20 А). Разъёмы платы `+12V`/Power Output (XH-2.54, ключи FDS9926A через 74HC595) **не тянут 13 А** — их не использовать.

С платы идут только два слаботочных сигнала и общая земля:

### 2.1. Сигнал скорости — ШИМ + RC-фильтр

STM32F407 имеет ЦАП только на PA4/PA5, а они заняты (`STCP_PA4` сдвигового регистра и `SPI1_SCK_PA5`). Поэтому — ШИМ, сглаженный в постоянное напряжение.

- Выход: **PWM8 = PA3, TIM5_CH4** (`PWM_OUTPUT_8`, группа `PWM_GROUP_5678`, разъём PWM8 внизу платы, контакт PWM; +6V не использовать).
- Частота: **20 кГц**, разрешение не хуже ~8 бит (см. п. 3.3).
- Снаружи: PA3 → **10 кОм** → средний провод потенциометра; от этой точки **1–10 мкФ** на GND. Потенциометр отпаян, его опорный провод (3,3–5 В) заизолирован, земляной провод — на GND.
- На выходе фильтра `U ≈ 3,3 В × duty`.

Почему PWM8, а не PWM1–4 (TIM4): группа 1234 по умолчанию 50 Гц под RC-сервы и H-мосты, на её выводах сидят отладочные `LL_GPIO_TogglePin(GPIOD, PWM2_PD14)`. Группа 5678 (TIM5) в коде используется только в `DemoTask`, а её создание в `main.c` закомментировано — но **это нужно подтвердить** (см. «Открытые вопросы»). После изменения частоты TIM5 каналы PWM5–8 нельзя использовать под RC-сервы.

### 2.2. Кнопка — MOSFET 2N7000

Транзистор подключается параллельно родной кнопке и «нажимает» её по команде.

| 2N7000 (TO-92, плоской стороной к себе: S-G-D) | Куда |
|---|---|
| D (сток) | сигнальный провод кнопки |
| S (исток) | GND |
| G (затвор) | вывод STM32 (п. ниже); + **100 кОм** с затвора на GND |

- Вывод: **GPIO5 = PA8** на 28-пиновом разъёме (контакт 5). По коду (`grep`) он нигде не используется — **перепроверить** и подтвердить у пользователя.
- На 28-пиновом разъёме каждый вывод проходит через 1 кОм + 100 нФ + диод на +5 В (схема «Board GPIO»). Для затвора MOSFET это нормально: фронт ~0,1 мс при импульсе 200 мс. Внешний резистор в затвор не обязателен.
- Логика: **HIGH = кнопка нажата**, LOW = отпущена. После сброса и до инициализации вывод должен быть LOW (подтяжка 100 кОм это гарантирует аппаратно; программно — сразу настроить как push-pull и сбросить в 0).

### 2.3. Общая земля

Минус аккумулятора турбинки соединён с GND платы. Без этого не работает ни сигнал скорости, ни кнопка.

## 3. Что реализовать в прошивке

### 3.1. Файлы

Следуй существующей структуре и `CodeStyle.txt` (функции PascalCase, переменные snake_case, модуль = `const struct` с указателями на функции, как `PWM`, `H_Bridge`, `RC_Servo`).

| Файл | Содержимое |
|---|---|
| `Core/Lib/impeller.c`, `Core/Lib/Include/impeller.h` | Низкий уровень: инициализация выводов/ШИМ, `SetSignalVolts()`, `SetButton(bool)`. Без задержек и без FreeRTOS |
| `Core/OS_Tasks/impeller_task.c` + объявление в `os_tasks.h` | Задача FreeRTOS (статическое выделение, по образцу `template_task.c`): автомат состояний, плавный разгон/торможение, неблокирующий импульс кнопки |
| `Core/App/Include/terminal_cmd_table.h`, `Core/App/terminal_cmd_handlers.c` | Команда терминала (п. 3.4) |
| `Core/App/main.c` | Инициализация и создание задачи |
| `cmake/sources.cmake` | Добавить новые `.c` в `EUROBOT_SOURCES` |
| `Core/App/Include/robot_gpio_defines.h` | `#define IMPELLER_BTN_GPIO5_PA8 GPIO5_PA8` и аналогично для сигнала, чтобы назначение выводов было в одном месте |

### 3.2. API модуля (предложение)

```c
enum impeller_state_e { IMPELLER_OFF, IMPELLER_STARTING, IMPELLER_ON, IMPELLER_STOPPING };

struct impeller_s {
  void (*Init)(void);
  void (*TurnOn)(void);                 // запрос: «нажать» кнопку, потом разрешить скорость
  void (*TurnOff)(void);                // запрос: плавно до 0, потом «нажать» кнопку
  void (*SetSpeed)(uint8_t percent);    // 0..100, с учётом IMPELLER_MAX_SPEED_PCT
  void (*SetRawVolts_mV)(uint16_t mv);  // калибровка: прямое напряжение сигнала
  void (*PressButton)(uint16_t ms);     // отладка: одиночное нажатие заданной длины
  enum impeller_state_e (*GetState)(void);
  uint8_t (*GetSpeed)(void);            // текущая скорость после рампа
};
extern const struct impeller_s Impeller;
```

Вызовы из терминала только выставляют запросы (переменные/флаги или очередь), всю работу с задержками делает `ImpellerTask` — терминал не должен блокироваться на 200 мс + разгон.

### 3.3. Поведение и параметры

- Константы в начале `impeller.c` или в `impeller.h`: `IMPELLER_V_MIN_MV`, `IMPELLER_V_MAX_MV`, `IMPELLER_V_STOP_MV` (0), `IMPELLER_INVERT` (0), `IMPELLER_PRESS_MS` (200), `IMPELLER_BOOT_DELAY_MS` (1000), `IMPELLER_MAX_SPEED_PCT` (на первые тесты 30), `IMPELLER_RAMP_PCT_PER_S` (40), `IMPELLER_PWM_FREQ_HZ` (20000).
- Пересчёт: `percent == 0` → `V_STOP`; иначе `V = V_MIN + (V_MAX − V_MIN) × percent / 100`; `duty = V / 3300 мВ`.
- **ШИМ-разрешение:** `PWM.SetGroupFrequency()` оставляет предделитель TIM5 = 83 (тик 1 МГц), на 20 кГц это ARR = 49 — всего 50 шагов. Нужно ≥ 256 шагов: в инициализации импеллера поставь предделитель TIM5 = 0 (тик 84 МГц, ARR = 4199) и задавай скважность через `PWM.SetOutput_CC()`, а не `SetOutputDutyCycle()` (у неё шаг 1 %). TIM5 32-битный, переполнения не будет. Задокументируй, что после этого `RC_Servo` на каналах 5–8 использовать нельзя.
- `TurnOn`: скорость = 0 → импульс кнопки `IMPELLER_PRESS_MS` → пауза `IMPELLER_BOOT_DELAY_MS` → состояние `ON`. Повторный `TurnOn` в состоянии `ON` игнорируется.
- `TurnOff`: плавно до 0 → пауза ~300 мс → импульс кнопки → `OFF`.
- Прошивка не знает реальное состояние контроллера турбинки (кнопка — переключатель). Состояние хранится программно; это ограничение нужно описать в документации. Обратной связи нет.
- Рамп в задаче с периодом 10–20 мс.

### 3.4. Безопасность

- После сброса: сигнал скорости = `V_STOP`, кнопка отпущена. Ничего не «нажимать» автоматически.
- **Конец матча:** в `game_task.c` есть таймер конца матча (`EUROBOT_MATCH_TIMEOUT`, 99 с), по которому выставляется `COMM_ENABLE = 0` и останавливаются приводы. Импеллер должен останавливаться там же (`TurnOff`), а команды включения при `COMM_ENABLE == 0` игнорируются. В пресете `bench` (`EUROBOT_MATCH_TIMEOUT=OFF`) не останавливать.
- `IMPELLER_MAX_SPEED_PCT` ограничивает любую команду скорости.

### 3.5. Команда терминала

Добавить в `terminal_cmd_table.h` следующую свободную команду и **обновить `TERMINAL_CMD_TABLE_SIZE`**:

```c
#define BOARD_IMPELLER                      0x30    /* [48] Impeller: on/off/speed/status */
#define TERMINAL_CMD_TABLE_SIZE             (BOARD_IMPELLER + 1)
```

Формат (предложение, согласовать с пользователем — см. «Открытые вопросы»):

| data[0] | Действие | Доп. данные |
|---|---|---|
| 0 | выключить (`TurnOff`) | — |
| 1 | включить (`TurnOn`) | — |
| 2 | скорость | data[1] = 0..100 % |
| 3 | статус | — |
| 4 | калибровка: напряжение | data[1..2] = мВ (uint16, разбирать через `ByteTo_Word16`, как в остальных командах) |
| 5 | отладка: нажать кнопку | data[1..2] = мс |

Ответ: `cmd = BOARD_IMPELLER`, `data[0] = 0x01` (принято) или `0x00` (ошибка длины/параметра), `data[1] = state`, `data[2] = текущая скорость %`. Проверяй `data_length` перед чтением `data[i]`. Учитывай флаг `COMM_ENABLE`, как это делают соседние обработчики.

`debug_terminal_cmd_handlers` использует тот же `TERMINAL_CMD_TABLE_SIZE` — проверь, что увеличение размера ничего там не ломает (неуказанные элементы должны остаться `NULL`).

Заметка: в `terminal_task.c` проверка `terminal_cmd_handlers[cmd] != NULL` стоит **до** проверки `cmd < TERMINAL_CMD_TABLE_SIZE` — при команде за пределами таблицы это чтение за границей массива. Можно поменять условия местами (отдельным маленьким изменением, с записью в CHANGELOG).

## 4. Правила проекта

- Сборка только CMake + Ninja: `make` (Debug), `make release`, `make check`. Новые `.c` — в `cmake/sources.cmake`.
- Только LL-драйверы и статическое выделение памяти FreeRTOS.
- Не менять поведение TIM4 / PWM1–4, RC-серв, H-мостов, PCA9685, одометрии.
- Приоритет новой задачи — не выше `TerminalTask`-соседей, обязательно `vTaskDelay` в цикле (см. историю в `CHANGELOG.md`: задача без задержки однажды «съела» процессор и терминал перестал отвечать).
- Обновить `CHANGELOG.md` (раздел с датой) и `docs/USAGE_RU.md` (подключение, команда, калибровка).

## 5. Проверка

1. `make` и `make check` без ошибок и новых предупреждений.
2. Без турбинки, с мультиметром/осциллографом:
   - после сброса PA3 ≈ 0 В (после фильтра), PA8 = 0;
   - команда «скорость 50 %» после «включить» → на выходе RC-фильтра ≈ `V_MIN + (V_MAX−V_MIN)/2`, частота ШИМ на PA3 = 20 кГц;
   - «нажать кнопку 200 мс» → на PA8 импульс 3,3 В длиной 200 мс; на стоке 2N7000 в это время ≈ 0 В;
   - конец матча (не в `bench`) → сигнал скорости падает в `V_STOP`.
3. С турбинкой — только после подтверждения пользователя, турбинка закреплена, `IMPELLER_MAX_SPEED_PCT = 30`.

## 6. Открытые вопросы (спросить пользователя до реализации)

1. Свободны ли на роботе **PWM8 (PA3)** и **GPIO5 (PA8)**, или выбрать другие выводы? Используются ли где-то RC-сервы 5–8?
2. Номер и формат команды терминала (`0x30`, таблица выше) — подходит ли? Кто обновит клиент на верхнем уровне (пульт `robot_console_2026.py` / код на `reset10`)? В этом репозитории его нет.
3. Финальные калибровочные значения `V_MIN`, `V_MAX`, `PRESS_MS` — пользователь получит их на ESP32-стенде.
4. Нужно ли аппаратно обесточивать турбинку (отдельный MOSFET-ключ на 20–30 А) или достаточно кнопки.
