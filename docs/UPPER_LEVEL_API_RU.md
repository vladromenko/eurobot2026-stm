# API верхнего уровня Eurobot 2025

## Статус

`tools/eurobot_api.py` — минимальный синхронный Python API, совместимый с
текущей прошивкой без её изменения. Он отделяет протокол и команды робота от
интерфейса телеуправления. В качестве транспорта можно передать `serial.Serial`,
UART-мост или тестовую реализацию с методами `read`, `write` и `flush`.

## Подключение

Основная плата использует USART1: 921600 бод, 8 бит, без чётности, один стоп-бит,
без аппаратного и программного управления потоком.

```python
from tools.eurobot_api import Pose, Velocity, open_serial_api

robot, port = open_serial_api("/dev/ttyUSB0")
try:
    robot.ping()
    robot.set_pose(Pose(0.0, 0.0, 0.0))
    robot.set_velocity(Velocity(0.2, 0.0, 0.0))
finally:
    try:
        robot.stop()
    finally:
        port.close()
```

`dx` и `dy` задаются в м/с, `dphi` — в рад/с; `x` и `y` возвращаются в метрах,
`phi` — в радианах. Многобайтовые значения передаются little-endian.

## Кадр HL-RTU

```text
FF FF LENGTH COMMAND DATA... CHECKSUM
```

- `LENGTH = len(DATA) + 2`;
- максимальный размер `DATA` — 32 байта;
- `CHECKSUM = ~(LENGTH + COMMAND + sum(DATA)) & 0xFF`;
- ответ использует тот же код команды;
- одна команда должна получить один ответ до отправки следующей команды.

## Реализованные команды

| Код | Метод Python | Запрос | Ответ |
|---:|---|---|---|
| `0x00` | `ping()` | — | — |
| `0x02` | `get_ax_angle(id)` | `<B` | `<BH`: status, angle |
| `0x03` | `set_ax_angle(id, angle)` | `<BH` | — |
| `0x04` | `set_velocity(Velocity)` | `<fff` | — |
| `0x05` | `get_velocity()` | — | `<fff` |
| `0x06` | `set_pose(Pose)` | `<fff` | — |
| `0x07` | `get_pose()` | — | `<fff` |
| `0x08` | `get_battery_state()` | — | 18 байт BMS |
| `0x09` | `set_bms_calibration(reg, value)` | `<BH` | — |
| `0x0A` | `set_gripper(state)` | `<B` | — |
| `0x0B/0x0C` | `set_pump(bool)` | — | — |

## Как добавлять новые механизмы

На первом этапе для каждого атомарного действия механизма следует добавить
отдельную команду запрос/ответ. Команда изменения состояния подтверждается
пустым ответом только после принятия значения. Команда чтения возвращает
фактическое состояние, а не последнее заданное значение.

Рекомендуемое следующее расширение протокола:

| Код | Назначение | Формат |
|---:|---|---|
| `0x0D` | `GET_API_INFO` | ответ `<BBI`: major, minor, feature flags |
| `0x0E` | `STOP_ALL` | пустой запрос и ответ |
| `0x0F` | `GET_FAULTS` | ответ `<I`: bitmap ошибок |
| `0x10+` | команды новых механизмов | фиксированные бинарные структуры |

Перед реализацией команды механизма нужно определить:

1. допустимые состояния, единицы и диапазоны значений;
2. безопасное состояние после включения и потери связи;
3. время выполнения и является ли команда блокирующей;
4. способ сообщить `busy`, ошибку концевика или привода;
5. требуется ли периодический heartbeat верхнего уровня.

В прошивке код добавляется в `Core/App/Include/terminal_cmd_table.h`, обработчик —
в `Core/App/terminal_cmd_handlers.c`, после чего обновляется таблица
`terminal_cmd_handlers` и `TERMINAL_CMD_TABLE_SIZE`. В Python добавляется значение
`Command` и типизированный метод `EurobotAPI`.

Нельзя переиспользовать существующий номер команды с другим форматом. Пока в
прошивке нет номера версии протокола, несовместимые изменения существующих
структур запрещены.

## Ограничения версии 1

- протокол строго запрос/ответ и не передаёт события асинхронно;
- нет встроенного номера последовательности и повторная отправка команды может
  повторно запустить действие;
- нет общей команды аварийного останова и watchdog связи;
- прошивка не возвращает версию API или список поддержанных механизмов;
- CRC фактически является однобайтной контрольной суммой, а не CRC.

До устранения этих ограничений верхний уровень должен иметь собственный таймаут,
не отправлять параллельные запросы и при завершении всегда посылать нулевую
скорость. `EurobotAPI` сериализует запросы блокировкой и проверяет длину ответов.

## Проверка без робота

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют формат пакета, checksum, little-endian `float32`, фильтрацию шума
до заголовка и контроль длины ответа.
